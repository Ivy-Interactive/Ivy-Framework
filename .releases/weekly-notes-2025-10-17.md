# Ivy Framework Weekly Notes - Week of 2025-10-17

## 🔧 CLI & Tooling Improvements

### New Sliplane Deployment Support
The Ivy CLI now supports deploying applications to **Sliplane**, a modern container deployment platform. Sliplane joins the existing deployment options alongside AWS, Azure, and GCP, providing developers with another streamlined deployment choice.

**Key Sliplane features:**
- Container hosting and deployment
- Automated SSL/TLS certificates
- Load balancing and traffic routing
- Automated health checks and monitoring

**Getting started with Sliplane:**
```terminal
>ivy deploy
# Select Sliplane when prompted
# Configure server and deployment settings
```

**Prerequisites:** Create a Sliplane account and generate an API key from your dashboard. You can optionally create a server beforehand, or let Ivy create one automatically during deployment.

### Fixed `ivy init` Command for Common Repository Files
The `ivy init` command now properly handles directories that contain common repository files like `.gitignore` and `README.md`. Previously, these files would cause the initialization to fail with an "empty directory" validation error, even though they're typically present in new repositories. The command now correctly ignores these common files when checking if a directory is suitable for initialization.

### Enhanced Database Generator Reliability
The database generator now automatically ensures that required .NET tools (specifically `dotnet-ef`) are installed before proceeding with database operations. This prevents errors that could occur when Entity Framework tools are missing from your development environment.

### Improved Loading Screen
The CLI updater now displays loading messages with better typography, showing "Updating Ivy.Console..." as a proper heading (H2) instead of plain text, providing a more polished user experience during updates.

### MCP Documentation Tool
A new documentation tool has been added to the CLI's MCP (Model Context Protocol) server, giving you instant access to comprehensive Ivy Framework documentation directly from your development environment. The tool can:

- **Browse by category**: Access documentation organized by topics like onboarding, widgets, API reference, console commands, authentication, database integration, and deployment
- **Search across all docs**: Find relevant information quickly with full-text search across the entire documentation library
- **Direct topic access**: Get specific documentation instantly by topic name

Example usage in MCP-enabled environments:
```json
// List all available topics
{ "topic": "list" }

// Browse widgets documentation
{ "category": "widgets" }

// Search for deployment information
{ "search": "deploy" }

// Get specific topic
{ "topic": "getting-started/introduction" }
```

The tool dynamically discovers documentation from the framework and fetches content directly from GitHub, ensuring you always have access to the latest information.

## 🔐 Authentication Improvements

### Auth0 Configuration Update - Breaking Change
The Auth0 authentication provider now **requires** the `Auth0:Audience` parameter to be configured. Previously, this parameter was optional with an empty string default, but it's now mandatory for proper Auth0 integration.

**Required configuration:**
```json
{
  "Auth0": {
    "Domain": "your-domain.auth0.com",
    "ClientId": "your-client-id", 
    "ClientSecret": "your-client-secret",
    "Audience": "https://your-domain.auth0.com/api/v2",
    "Namespace": "https://ivy.app/"
  }
}
```

### Updated Environment Variable Names
The documentation now correctly reflects the proper .NET configuration format for environment variables:

**Windows (PowerShell):**
```powershell
$env:Auth0__Domain="your-domain.auth0.com"
$env:Auth0__ClientId="your-client-id"
$env:Auth0__ClientSecret="your-client-secret"
$env:Auth0__Audience="https://your-domain.auth0.com/api/v2"
$env:Auth0__Namespace="https://ivy.app/"
```

**Mac/Linux (Bash):**
```bash
export Auth0__Domain="your-domain.auth0.com"
export Auth0__ClientId="your-client-id"
export Auth0__ClientSecret="your-client-secret"
export Auth0__Audience="https://your-domain.auth0.com/api/v2"
export Auth0__Namespace="https://ivy.app/"
```

### BasicAuth Parameter Clarification
The BasicAuth documentation has been updated to clarify parameter requirements and naming:

- **BasicAuth:Users**: Required runtime parameter containing hashed passwords
- **BasicAuth:HashSecret**: Required secret for password verification (auto-generated by `ivy auth add`)
- **BasicAuth:JwtSecret**: Required key for token generation (auto-generated by `ivy auth add`)

The documentation now clearly explains the difference between parameters provided to `ivy auth add` (plaintext passwords) versus runtime configuration (hashed passwords).

## 🧪 Testing Improvements

### Enhanced Card Widget Testability
Card widgets now have improved support for automated testing with the addition of the `TestId()` method. This allows you to assign test identifiers to Card widgets for more reliable end-to-end testing.

**Example usage:**
```csharp
var card = new Card("Card content")
    .Title("My Card")
    .Description("Card description")
    .TestId("my-card-identifier");
```

The Card widget now also includes proper accessibility attributes (`role="region"`) and supports `data-testid` attributes in the rendered HTML, making it easier to write reliable automated tests with tools like Playwright, Selenium, or Cypress.

## 🐛 Error Handling Improvements

### Enhanced AppHub Error Reporting
The SignalR AppHub now provides more detailed error information when connection failures occur. Instead of generic error messages, clients now receive structured error responses with comprehensive debugging information.

**Improved error response structure:**
```javascript
// Previous error format
{
  "message": "Failed to establish connection",
  "error": "Exception message"
}

// New enhanced error format  
{
  "title": "Internal Server Error",
  "description": "Detailed exception message",
  "stackTrace": "Full stack trace for debugging"
}
```

This improvement helps developers debug connection issues more effectively by providing the complete stack trace and a clearer error structure. The enhanced error reporting is automatically available to all SignalR clients connecting to Ivy applications.

## 📊 New DataTable Widget - High-Performance Data Display

### Powerful Data Tables with Apache Arrow

A new `DataTable` widget has been introduced for displaying and interacting with large datasets. Built on Apache Arrow technology, it provides exceptional performance with big data while offering modern data table features like sorting, filtering, pagination, and real-time updates.

**Key features:**
- **High-performance**: Powered by Apache Arrow for optimal performance with large datasets
- **Automatic scaffolding**: Detects model properties and creates appropriate columns automatically
- **Intelligent column types**: Automatically detects and handles Text, Number, Boolean, Date/DateTime, and Icon data types
- **Flexible customization**: Easy to customize headers and column behavior while maintaining defaults for everything else

**Basic usage:**
```csharp
// Convert any IQueryable<T> to a DataTable
sampleUsers.ToDataTable()
    .Header(u => u.Name, "Full Name")
    .Header(u => u.Email, "Email Address") 
    .Header(u => u.Salary, "Salary")
    .Header(u => u.Status, "Status");
```

**Column type features:**
- **Text columns**: String and character data with standard text formatting
- **Number columns**: Numeric values (int, decimal, double, etc.) with proper alignment
- **Boolean columns**: True/false values displayed as checkboxes
- **Date/DateTime columns**: Formatted date and time values
- **Icon columns**: Icon enum values rendered as visual icons

The DataTable provides automatic scaffolding - you only need to customize what you want to change, while everything else gets sensible defaults based on your model properties.

## 📝 Forms System Overhaul

### Simplified Form Submission - Breaking Change
Forms now handle submission automatically! The old `.UseForm()` pattern has been replaced with a much simpler approach where forms automatically handle Enter key presses and update model state directly.

**Previous approach (deprecated):**
```csharp
// Old complex pattern - no longer needed
var (onSubmit, formView, validationView, loading) = formBuilder.UseForm(this.Context);

async ValueTask HandleSubmit()
{
    if (await onSubmit())
    {
        // Handle success
    }
}
```

**New streamlined approach:**
```csharp
public class ContactFormExample : ViewBase
{
    public override object? Build()
    {
        var contact = UseState(() => new ContactModel("", "", ""));
        var client = UseService<IClientProvider>();

        // React to form submission with UseEffect
        UseEffect(() =>
        {
            if (!string.IsNullOrEmpty(contact.Value.Name))
            {
                client.Toast($"Message from {contact.Value.Name} sent successfully!");
            }
        }, contact);

        // Forms now handle submission automatically
        return contact.ToForm()
            .Required(m => m.Name, m => m.Email, m => m.Message);
    }
}
```

**Key improvements:**
- **Automatic Enter key handling**: Pressing Enter moves to the next field, or submits when on the last field
- **Auto-blur validation**: Fields validate automatically when you move away from them
- **Direct state updates**: Forms update the model state directly when submitted successfully
- **Invalid field navigation**: If there are validation errors, Enter key moves to the first invalid field instead of submitting

### Enhanced Form Validation

**Automatic email validation**: Fields ending with "Email" now automatically get proper email validation using .NET's built-in `EmailAddressAttribute`.

**DataAnnotations support**: Forms now automatically respect standard .NET validation attributes:
```csharp
public record UserModel(
    [Required, MinLength(3)] string Username,
    [EmailAddress] string Email,
    [Required, MinLength(8)] string Password
);

// Validation rules are automatically applied - no manual setup needed!
var form = userModel.ToForm();
```

**Improved validation timing**: Default validation strategy is now `OnBlur` (validates when field loses focus) instead of `OnSubmit`, providing immediate feedback to users.

### Enhanced Form Widget Integration
The frontend Form widget now includes better keyboard navigation and accessibility features:
- Enter key properly moves between fields and triggers submission on the last field
- Invalid fields are properly marked with `data-invalid-icon` attributes for testing
- Improved focus management and blur handling

## 🔍 App Discovery Enhancement

### Search Hints for App Attributes
The `[App]` attribute now supports a `searchHints` property that allows you to specify alternative keywords for search discoverability. This enhancement makes your apps easier to find when users search using different terminology than your app's title or path.

**New `[App]` attribute properties:**
- `searchHints`: Array of alternative keywords for search discoverability
- `order`: Sort order within group  
- `description`: Brief description of the app

**Example usage:**
```csharp
[App(icon: Icons.TextCursorInput,  
     path: ["Widgets", "Inputs"],  
     searchHints: ["password", "textarea", "search", "email"])]
public class TextInputApp : ViewBase
{
    public override object? Build()
    {
        return Text.H1("Text Input Examples");
    }
}
```

This allows users to find your TextInputApp by searching for "password", "textarea", "search", or "email" in addition to the standard "TextInputApp" or "Inputs" terms. The feature works seamlessly with the enhanced documentation search system to provide better content discovery.
