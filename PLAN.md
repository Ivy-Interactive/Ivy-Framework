# План: LLM-ориентированные файлы (`llms.txt`), генерируемые на бэкенде

## Обзор

Во фронтенде уже есть функциональность копирования/скачивания, которая извлекает содержимое отрендеренной markdown‑страницы (включая результаты, сформированные на лету — секции API). В бэкенде такой функциональности пока нет. Цель — вычислять это содержимое во время выполнения `.Regenerate`, создавая для каждого `.md` файла отдельный `llms.txt` файл (каноническое название для LLM‑ориентированных файлов), который содержит всю информацию, аналогичную функции copy/md во фронтенде, и затем отдавать эти файлы через Ivy.Docs по отдельному endpoint для LLM.

## Текущее состояние

### Функциональность копирования/скачивания во фронтенде (`DocumentTools.tsx`)
- Разворачивает все блоки с подробностями (`details` / раскрывающиеся секции)
- Загружает содержимое всех вкладок
- Извлекает API‑секции из отрендеренного DOM:
  - Заголовки (h1–h6)
  - Параграфы
  - Списки (ul, ol)
  - Таблицы
  - Блоки кода (включая терминальные блоки)
  - API‑секции (Constructors, Properties, Events, Supported Types)
  - Блоки с подробностями/раскрывающиеся секции
- Конвертирует отрендеренный HTML/DOM обратно в markdown
- Позволяет скопировать в буфер обмена и скачать как `.md` файл

### Процесс регенерации на бэкенде
- Скрипты `Regenerate.sh` / `Regenerate.ps1` запускают `Ivy.Docs.Tools`
- `ConvertCommand` обрабатывает все `.md` файлы в директории `Docs/`
- `MarkdownConverter.ConvertAsync()` конвертирует каждый `.md` файл в C#‑файл `.g.cs`
- Сгенерированные файлы попадают в директорию `Generated/`
- Цель MSBuild `TransformMarkdown` запускает это во время сборки

### Генерация API во время выполнения (`WidgetDocsView.cs`)
- Во время выполнения с помощью reflection генерируются секции API:
  - **Constructors**: извлекаются из конструкторов типов и extension‑методов
  - **Supported Types**: для input‑виджетов отображаются поддерживаемые типы состояния
  - **Properties**: свойства с атрибутом `[Prop]`
  - **Events**: свойства с атрибутом `[Event]`
- Эти секции рендерятся как таблицы и markdown в UI
- Сейчас они доступны только во время выполнения, но не во время регенерации

## Цели

1. **Вычисления на бэкенде**: генерировать `llms.txt` файлы во время выполнения `.Regenerate`, которые включают:
   - Исходное markdown‑содержимое из `.md` файлов
   - Секции API, сгенерированные на основе runtime‑логики (Constructors, Properties, Events, Supported Types)
   - Полностью развёрнутые блоки подробностей (`details`)
   - Содержимое всех вкладок
   - Блоки кода и терминальные блоки
   - Таблицы с привязанным к ним контентом

2. **Генерация файлов**: для каждого сгенерированного `.g.cs` файла в `Generated/` создавать соответствующий `llms.txt` файл в той же директории

3. **Отдача файлов**: добавить поддержку в `Ivy.Docs` для выдачи `llms.txt` файлов по URL того же вида, что и обычная страница, но с суффиксом `llms.txt`, например:  
   - страница: `https://docs.ivy.app/onboarding/getting-started/introduction`  
   - LLM‑версия: `https://docs.ivy.app/onboarding/getting-started/introduction.llms.txt`

## Технические детали и ограничения

### Разрешение типов виджетов
- **Текущий подход**: Типы извлекаются из атрибута `Type` в блоке `<WidgetDocs Type="..."/>`
- **Разрешение типов**: Использовать `TypeUtils.GetTypeFromName()` (как в `WidgetDocsView`)
- **Загрузка сборок**: Необходимо убедиться, что все нужные сборки загружены для reflection
- **Обработка ошибок**: Если тип не найден, пропустить API‑секцию или добавить предупреждение в markdown

### Конвертация таблиц в markdown
- **Простые таблицы**: Прямое извлечение данных из `TableRow` и `TableCell`
- **Сложные ячейки**: Таблицы Supported Types содержат `Vertical()` layout с типами
  - Необходимо извлечь текстовое содержимое из вложенных виджетов
  - Возможные варианты: рекурсивный обход виджетов или использование `ToString()` методов
- **Форматирование**: Обеспечить корректное выравнивание колонок в markdown

### Обработка Details блоков
- **Текущая реализация**: `MarkdownConverter` уже парсит `<Details>` блоки
- **Подход**: Использовать существующую логику из `HandleDetailsBlockDirect()`
- **Разворачивание**: Извлечь summary как заголовок, body как развёрнутое содержимое
- **Рекурсия**: Body может содержать вложенные Details блоки — нужна рекурсивная обработка

### Обработка вкладок (Tabs)
- **Обнаружение**: Искать блоки кода с аргументом `demo-tabs` в markdown
- **Извлечение**: Из сгенерированного C# кода можно извлечь структуру `Tabs()` с `Tab()` элементами
- **Альтернатива**: Парсить markdown напрямую, если структура вкладок определена в исходном markdown
- **Объединение**: Включить содержимое всех вкладок последовательно с заголовками

### Производительность
- **Reflection**: Генерация API через reflection может быть медленной
  - Решение: Кешировать информацию о типах между файлами
  - Использовать параллельную обработку из `ConvertCommand`
- **Парсинг markdown**: Использовать существующий `MarkdownPipeline` для консистентности
- **Файловые операции**: Минимизировать количество чтений/записей файлов

### Организация файлов
- **Решение**: `llms.txt` файлы создаются в `Generated/` с той же структурой директорий, что и `.g.cs`
- **Преимущества**:
  - Все сгенерированные файлы в одном месте
  - Простая структура для endpoint (маппинг URL → файл)
  - Соответствие существующей архитектуре
- **Пример структуры**:
  ```
  Generated/
    Onboarding/
      GettingStarted/
        Introduction.g.cs
        Introduction.llms.txt
  ```

### Endpoint и маршрутизация
- **Формат URL**: `/{path}.llms.txt` (например, `/onboarding/getting-started/introduction.llms.txt`)
- **Маппинг**: URL → `Generated/{Path}.llms.txt` (с преобразованием пути)
- **Архитектура Ivy**: Необходимо изучить, как Ivy обрабатывает маршруты и статические файлы
- **Альтернатива**: Если Ivy не поддерживает такие маршруты напрямую, использовать middleware или кастомный обработчик
